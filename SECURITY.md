# Security policy

## Reporting a vulnerability

If you find a security problem in this repository — a formula or script that could be abused, a detection rule that
can be trivially bypassed in a way the documentation does not state, a dependency issue, or any content that could
put a user at risk — please report it privately:

1. **GitHub private vulnerability reporting** — open the *Security* tab of this repository and choose
   *Report a vulnerability*. This is the preferred channel.
2. Or through the contact section of [my portfolio](https://bizidwassim-design.github.io/wassim-bizid-portfolio/#contact).

Please do **not** open a public issue for security reports.

You will receive an acknowledgement within **5 business days** and a resolution or a status update within **30 days**.
Credit is given in the changelog unless you prefer to stay anonymous.

## Scope

* All files in this repository (templates, rules, scripts, documentation, web assets).
* The GitHub Pages site built from this repository, where one exists.

Out of scope: the standards referenced (ISO, NIST, CIS, MITRE), third-party libraries loaded from a CDN (report those
upstream), and the way you deploy or adapt the content in your own environment.

## Supported versions

Only the latest commit on `main` is supported. Download templates from the latest release or from `main`.

## Design commitments

* No macros, no executable content in office documents; workbooks are generated by reviewable Python scripts.
* No telemetry, analytics or tracking in any web asset; third-party scripts are pinned and integrity-checked.
* No real indicators, credentials, client names or internal data — fictional samples only.
